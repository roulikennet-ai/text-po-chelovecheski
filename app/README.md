# Текст по-человечески

Редактор научного текста, который переписывает прозу по-человечески и **не меняет ни одного факта**: числа, имена, аббревиатуры, латиница, URL и ссылки на источники защищены на уровне конвейера, а не на уровне «модель попросили».

Веб-приложение на React + TypeScript + Vite. Собирается и в веб, и в десктопное приложение Tauri (`.exe` + установщик).

---

## Что умеет

| Возможность | Где |

## Запуск

**Быстрый старт (Windows):** двойной клик по `start.cmd` в корне проекта — установит зависимости (если нужно), запустит dev-сервер и откроет браузер.

```bash
cd app
npm install
npm run dev      # http://localhost:5173
```

С корневого каталога:

```bash
npm run dev      # тоже самое, без cd
```

Web-версия с GigaChat (ключ хранится на сервере, в браузер не попадает):

```bash
copy .env.example .env   # и вписать GIGACHAT_AUTH_KEY
npm run web:build        # сборка + web-сервер на http://127.0.0.1:4173
```

Подробная инструкция: [WEB_README.md](WEB_README.md).

Сборка:

```bash
npm run build    # tsc --noEmit && vite build → dist/
npm run preview
npm run typecheck
npm run smoke    # смоук-тест ядра: защита, движок, валидация, экспорт
npm run probe    # корпус 8 текстов × F1–F4 × уровни 1–5: грамматика и сохранность фактов
npm run abort-check   # пауза/стоп: отмена не превращается в локальный пересказ
npm run batch-check   # пакетная обработка: пауза, стоп, смена проекта, сбой движка
npm run engine-check  # выбор движка: правила / GGUF / облако
```

## Локальная модель (GGUF)

«Настройки» → «Локальная модель». Два пути:

1. **Скачать по ссылке** — выберите пресет (Qwen2.5 0.5B/1.5B/3B, Llama 3.2 3B) или вставьте
   прямой адрес `.gguf`. Файл кэшируется в браузере, дальше модель работает офлайн.
2. **Файл с диска** — скачайте `.gguf` вручную и укажите файл. Работает без сети и без CORS;
   после перезагрузки страницы файл нужно выбрать заново.

Модель считается в WebAssembly (`@wllama/wllama`), библиотека грузится лениво — основной
бандл не растёт. Нужно ~4 ГБ свободной памяти для модели на 3B. Выгрузить модель и очистить
кэш можно там же. Если скачивание большого файла обрывается — используйте «Файл с диска».

## Десктопная сборка (Tauri)

Нужны Rust (toolchain `stable-x86_64-pc-windows-msvc`), MSVC Build Tools с C++ и WebView2 Runtime.

```bash
npm run icon      # app-icon.png → src-tauri/icons/ (icon.ico, icon.icns, PNG-набор)
npm run app:build # release .exe + установщик
```

Артефакты:

- `src-tauri/target/release/text-po-chelovecheski.exe` — портативный `.exe` (~11 МБ), запускается без установки;
- `src-tauri/target/release/bundle/nsis/Текст по-человечески_1.0.0_x64-setup.exe` — установщик (~2,2 МБ).

`npm run app:dev` поднимает `vite` и открывает приложение в нативном окне с горячей перезагрузкой.

**Про MSI.** Собирается только NSIS: MSI-упаковщик WiX по умолчанию использует codepage 1252 и падает с `LGHT0311` на кириллическом `productName`. NSIS работает с Unicode из коробки, поэтому выбран он. Если MSI обязателен — либо латинский `productName`, либо кастомный WiX-шаблон с `Codepage="65001"`.


## Гарантия неизменяемого — как это сделано

Не «попросили модель не менять числа», а физически не дали ей их увидеть:

1. **Токенизация.** Защищённые фрагменты изымаются из текста и заменяются токенами `⟦Ч12⟧`, `⟦И1⟧`… (`core/protection.ts`).
2. **Генерация.** Движок получает только маскированный текст. Вернуть токен он может лишь дословно.
3. **Возврат.** Токены разворачиваются обратно в исходные строки байт-в-байт.
4. **Валидация.** Проверяются факты (R1–R6), порядок абзацев, сила утверждения и отрицания. Не прошло — авторетрай (до 2 попыток), затем статус «требует внимания» или «ошибка».
5. **Экспорт.** Документ с 🔴 ошибками выгружается только после явного подтверждения.

Порядок абзацев, заголовки и цитаты не переставляются. Новые факты не добавляются — их просто неоткуда взять: модель работает с текстом, из которого удалены все числа и имена.

## Движки

`engines/engine.ts` задаёт единый интерфейс, поэтому переключение режима не меняет ни одной функции интерфейса.

- **Локально (правила).** `LocalRuleEngine` — без сети, мгновенно, всегда доступен. Снимает канцелярит и клише, дробит длинные предложения, разворачивает списки в прозу, добавляет связки. Качество — среднее, зато приватность абсолютная.
- **Локально (GGUF-модель).** `GgufEngine` — настоящая языковая модель в WebAssembly (`@wllama/wllama`).
  Скачивается один раз в «Настройках» и работает офлайн: ни текст, ни модель не покидают компьютер.
  Библиотека грузится лениво, поэтому основной бандл не растёт. Если в модели нет chat template,
  движок сам переходит на обычное продолжение текста по инструкции.
- **GigaChat.** `GigaChatEngine` — через локальный серверный прокси (`server/`).
  Ключ авторизации живёт только на сервере (`app/.env`), OAuth-токен кэшируется
  на 30 минут. Браузер отправляет уже маскированный текст. Подробности и
  инструкция по ключу: [WEB_README.md](WEB_README.md).
- **Облако (OpenAI-совместимое).** `CloudEngine` — любой OpenAI-совместимый endpoint (`apiBaseUrl`, `apiKey`, `cloudModel` в настройках). Таймаут 10 с, стриминг для точечного режима. Перед первым запуском показывается предупреждение об отправке текста (M1); согласие можно дать разово или постоянно.

Ключ API хранится в localStorage этого браузера/профиля и никуда, кроме указанного вами endpoint, не отправляется.

## Что не реализовано (следующий этап)

- **F3 «проза вместо списков» не подключён.** Функция `expandListToProse` в `core/ruleEngine.ts` написана, но пайплайн её не вызывает: каждый пункт списка обрабатывается отдельно, развёртывания в связную прозу нет. H1 при F3 требует ≥80 % развёрнутых списков — сейчас это не выполняется.
- Локальная GGUF-модель (3–4B) — сейчас офлайн-режим работает на правилах.
- SQLite вместо localStorage — интерфейс `state/storage.ts` уже изолирован под замену.
- Полный round-trip DOCX с сохранением вложенных таблиц (сейчас — плоский текст с абзацами).
- Недельный лимит с жёсткой блокировкой (счётчик и модалка есть, блокировки нет).
- Профиль стиля не передаётся в генерацию как few-shot примеры — только влияет на подсказки.

## Проверено

- `npm run typecheck` — без ошибок (strict, `noUnusedLocals`).
- `npm run build` — 1638 модулей, 361 КБ JS / 48 КБ CSS (113 КБ / 8 КБ gzip).
- `npm run app:build` — Rust-сборка за 4 мин, `.exe` 11 МБ + установщик NSIS 2,2 МБ; приложение запущено и открыло окно без ошибок в логе.
- `npm run smoke` — 131 проверка ядра: дословный round-trip защиты, отсутствие цифр в маске, сохранность фактов после переписывания, клише, R1–R6, разбор абзацев, конвейер, экспорт, плюс регрессии по всей матрице F1–F4 × уровни 1–5 и стоп-лист имён.
- `npm run probe` — корпус из 8 текстов × F1–F4 × уровни 1–5 (220 вариантов): **0 жёстких дефектов** — ни одной потери чисел, имён, аббревиатур и ссылок, ни одной смены силы утверждения, ни одного пустого результата. Остаются 105 пометок «БЕЗ ИЗМЕНЕНИЙ» — это тексты, где движку нечего править без риска (список без развёртывания в прозу, заголовок, абзац из одних защищённых фрагментов).
- Ручной прогон в браузере: вставка текста → авто-защита → запуск F1/уровень 3 → 7 абзацев разобраны → сравнение «было/стало» → отчёт смысла.

`probe` возвращает код 1 при любом жёстком дефекте, поэтому его можно ставить в CI.

### Что смоук-тест и probe поймали и что исправлено

- `\b` в JavaScript не работает с кириллицей: имена (`Иванов`) не находились вообще, а **словарь канцелярита не срабатывал ни на одной записи** (537 регэкспов в `lexicon.ts`). Заменено на lookaround-границы скриптом `scripts/fix-wordbounds.mjs`.
- Год «2015» маскировался как «201» — регэксп чисел резал по `\d{1,3}`. Переписано на «любая группа цифр + необязательные дроби/диапазоны/единицы».
- Версии стандартов (`ГОСТ Р 7.0.5-2008`) и градусы (`36,6 °C`) теперь защищаются целиком.
- Заголовок без маркера («Введение») распознаётся как заголовок.
- «в рамках» → «в» ломало падеж («в данного исследования») — оборот переведён в «в ходе».
- Связки вставлялись в придаточные («Поэтому, что позволяет…») — добавлена проверка по lookaround и запрет на придаточные зачины.
- Дробление длинного предложения шло по «что/который» и давало обрубки — теперь только по сочинительным союзам.
- После возврата токена «2015–2023 гг.» появлялось «гг..» — добавлена косметика `polishRestored` в конвейере.
- «Следует» в начале предложения считалось именем, и любая правка давала ложную «потерю факта» — стоп-лист `NOT_NAMES` вынесен из `protection.ts` и используется в `validation.ts`.

### Что нашёл расширенный корпус (второй проход)

- **`compress` в F2 выбрасывал предложения с числами** — прямая потеря фактов на любом тексте с цифрами. Теперь предложения с токенами защиты, кванторами и отрицаниями неприкосновенны; если их больше целевого объёма, сжатие отменяется.
- **Движок сам вставлял клише**: `CONNECTIVES` содержали «в итоге», «в результате», «при этом», «наряду с этим», «в то же время» — всё это есть в словаре клише, то есть текст «лечили» и тут же портили обратно. Список заменён на нейтральные связки без логических обязательств.
- **«Отсюда следует, что» превращало произвольный факт в вывод** — искажение смысла (R5/R6). Такие связки убраны.
- **`VO2max` и `HTML5` рвались на число + огрызок** (`VO` + `2`), а `СПбГУ` не защищался вовсе: латиница теперь обрабатывается до чисел, добавлена регулярка для аббревиатур смешанного регистра.
- **«в рамках данного исследования» → «в ходе»** давало клише в результате — заменено на падежно-нейтральные «в этом исследовании» / «в этой работе».
- **Запятая после «также»** («Также, задачи определены») — «также» добавлено в `NO_COMMA_CONNECTIVES`.
- **Строчная буква в начале предложения** после удаления связки в F4 (`trimLeadingConnective` не восстанавливал заглавную).
- **«Затем … Затем»** — связки ставились в каждое предложение подряд и раздували короткий текст на 36 %. Теперь не больше одной связки на два предложения, без повторов, и при приросте объёма выше 15 % связки отменяются.
- **Ложные «потери имён»** на каждом добавленном переходе: сравнение было регистрозависимым, а по правилам русского языка после связки слово пишется со строчной. Имена теперь сравниваются без учёта регистра и по тому же набору, который реально маскируется.
