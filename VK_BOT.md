# Бот сообщества ВКонтакте (Long Poll API)

Бот отвечает в сообщениях сообщества и показывает, **кто** обрабатывал текст в
приложении, **когда** и **сколько токенов** израсходовал. Тексты документов не
сохраняются и боту не передаются — только автор запроса, время и расход.

## Команды бота

| Команда | Что показывает |
| --- | --- |
| `report` | сводка за 7 дней и последние запросы одним сообщением |
| `/last` | последние 10 запросов: имя, дата и время, токены |
| `/stats` | сводка за 7 дней: запросы, ошибки, токены по моделям |
| `/stats 30` | то же за 30 дней (максимум 90) |
| `/top` | расход по пользователям за 7 дней, от большего к меньшему |
| `/user <id или имя>` | детально по одному пользователю и его последние запросы |
| `/help` | справка |

Слэш не обязателен: `report` и `/report` работают одинаково. Понимаются и
русские варианты: `отчет`, `отчёт`, `сводка`.

Писать можно двумя способами — оба поддерживаются:

- **Как пользователь**: открыть страницу сообщества → «Написать сообщение».
- **Из раздела «Сообщения»** в управлении сообществом, даже если отвечаете от
  имени сообщества. Бот отличает такие сообщения по `admin_author_id` и не
  путает их со своими ответами, поэтому зацикливания нет.

Кто «сделал запрос» бот берёт из приложения: пользователь указывает своё имя в
**Настройки → Чтение и лимиты → «Ваше имя в отчётах»**, плюс у каждой установки
есть анонимный `clientId`. Если имя не заполнено, бот покажет короткий ID.

## Шаг 1. Подготовить сообщество

1. Сообщество должно быть вашим (или у вас должны быть права администратора).
2. Включите сообщения: **Управление → Сообщения → «Сообщения сообщества»** —
   включено.
3. В **Управление → Сообщения → Настройки для бота** включите «Возможности
   ботов» (если пункт доступен для вашего типа сообщества).

## Шаг 2. Получить ключ доступа сообщества

1. **Управление → Настройки → Работа с API**.
2. **Создать ключ** → отметьте права:
   - **«Сообщения»** (обязательно);
   - **«Управление»** (нужно для Long Poll).
3. Скопируйте ключ. Он показывается один раз — сохраните его сразу.

Ключ **не нужно** присылать в чат, в переписку или в задачи. Вписывайте его
только в локальный файл `app/.env` (см. шаг 4).

## Шаг 3. Включить Long Poll и узнать ID сообщества

1. Там же: **Работа с API → Long Poll API** → «Включено».
2. Версия API — **5.199** или новее.
3. Типы событий → отметьте **«Входящее сообщение»** (`message_new`).
4. `VK_GROUP_ID` — это **число** (без `club` и без минуса). Его видно в адресе
   `vk.com/club123456789` или на странице **Управление → Настройки → Адрес**
   (раздел «ID»).

## Шаг 4. Куда вписать ключ

Файл: **`app/.env`** (в папке `app`, рядом с `package.json`). Он уже в
`.gitignore` и в репозиторий не попадает.

Если файла нет — создайте его копированием шаблона:

```bash
# из корня проекта
copy app\.env.example app\.env      # Windows cmd
# или: cp app/.env.example app/.env  # bash
```

Откройте `app/.env` любым редактором и добавьте строки (значения — свои):

```dotenv
# ключ сообщества с правами «Сообщения» и «Управление»
VK_ACCESS_TOKEN=ваш_ключ_сюда
# числовой id сообщества
VK_GROUP_ID=123456789
# кому разрешено пользоваться ботом: id пользователей ВК через запятую.
# Пусто — команды принимает любой участник сообщества.
VK_BOT_ADMINS=
# сколько секунд держать запрос Long Poll (по умолчанию 25)
VK_LONGPOLL_WAIT=25
```

Свой id пользователя ВК можно узнать на странице `vk.com/settings` (в адресе)
или командой `https://api.vk.com/method/users.get` — либо просто оставьте
`VK_BOT_ADMINS` пустым и ограничьте доступ настройками сообщества.

Ключ GigaChat (`GIGACHAT_AUTH_KEY`) лежит в том же файле — бот и web-сервер
читают его оттуда же.

Бот ищет ключи в двух местах: сначала в `app/.env`, затем в корневом
`.env.deploy` (тот же файл, что использует `docker compose`). Уже заданные
переменные не перезаписываются, поэтому можно держать один `.env.deploy` и для
Docker, и для локального запуска.

## Шаг 5. Запустить бота

Бот — отдельный процесс, работает рядом с web-сервером:

```bash
# из корня проекта
npm run vkbot

# или напрямую
cd app
npm run vkbot
```

При успехе в консоли будет:

```
[vkbot] запуск для сообщества 123456789
[vkbot] Long Poll подключён, ждём сообщения
```

Проверка: напишите сообществу `/help` — бот ответит списком команд.

## Как проверить отчёт

1. Запустите приложение (`npm start`) — метрики пишет web-сервер.
2. В приложении **Настройки → «Ваше имя в отчётах»** укажите имя, иначе в
   отчёте будет короткий ID установки.
3. Отправьте сообществу `report`. Если обработок ещё не было, бот ответит
   «запросов не было» — это ожидаемо.
4. Обработайте учебный текст в приложении (кнопка обработки).
5. Снова отправьте `report` и сравните: число запросов должно вырасти на один,
   а расход токенов — измениться на величину этого запроса.

Сравнивайте не конкретное число токенов, а факт роста: `Запросов: 1 → 2`,
`Токенов: 920 → 1 550`. В блоке «Последние запросы» появится новая строка с
именем, временем и токенами.

Метрики лежат в `app/data/metrics.json` (или в пути из `METRICS_FILE`). Если
файла нет — обработок через сервер ещё не было.


Чтобы бот работал постоянно, запускайте его так же, как сервер (systemd,
`pm2`, второй процесс в Docker Compose). Пример для Docker приведён в
`DEPLOY.md`.

## Частые ошибки

**`Access denied: no access to call this method. It cannot be called with
current scopes` (код 15)** — у ключа нет нужных прав. Проверьте по порядку:

1. Ключ создан как **«Ключ доступа сообщества»** в **Управление → Настройки →
   Работа с API → Ключи доступа сообщества**. Сервисный ключ и ключ
   пользователя для Long Poll **не подходят**.
2. При создании отмечены **«Сообщения сообщества»** и **«Управление
   сообществом»**. Прав `groups`/`stats` недостаточно.
3. **Работа с API → Long Poll API** включён, событие «Входящее сообщение»
   отмечено.
4. В **Управление → Сообщения** включены «Сообщения сообщества».

Права существующего ключа VK не меняет: создайте новый ключ с нужными правами,
отзовите старый и впишите новый в `app/.env`.

**`Long Poll API is disabled`** — не включён Long Poll API (см. шаг 3).

**`Incorrect group id` / `no access to this group` (код 15 на `groups.*`)** —
`VK_GROUP_ID` указан неверно или ключ выпущен для другого сообщества. Нужен
числовой id без `club` и без минуса.

**Бот молчит на команды** — проверьте, что сообщение пришло в **сообщения
сообщества**, а не на стену; что включены «Возможности ботов»; и что id
отправителя есть в `VK_BOT_ADMINS`, если список задан.

Если бот не отвечает на сообщения, отправленные **от имени сообщества** через
раздел «Сообщения», — проверьте, что у события есть `admin_author_id`
(обновление `vkbot.mjs` от 25.11.2026). Сообщения без него бот считает своими
ответами и пропускает, чтобы не зациклиться.

## Безопасность

- Ключ читается только серверным процессом и **никогда не печатается в логах**:
  `vkbot.mjs` маскирует токен и любые длинные строки в сообщениях об ошибках.
- Ключ не попадает в браузер и в ответы API.
- `app/.env` исключён из git. Не вставляйте ключ в код, в скриншоты и в чат.
- Если ключ засветился — отзовите его в **Работа с API** и создайте новый,
  затем обновите `app/.env` и перезапустите бота.

## Ограничения

- Бот видит только сообщения, пришедшие после его запуска (Long Poll начинает
  с текущего `ts`).
- Отчёты строятся по метрикам приложения: файл `app/data/metrics.json`
  (или путь из `METRICS_FILE`). Если метрик ещё нет, бот ответит «запросов не
  было».
- Имя в отчётах — то, что пользователь сам указал в настройках приложения;
  проверки личности нет, поэтому в проде бота лучше ограничить через
  `VK_BOT_ADMINS`.
